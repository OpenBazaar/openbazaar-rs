\paragraph{The ship-to ceiling.} For physical goods, the seller and the carrier learn where the buyer receives parcels. No protocol mechanism removes this, and we do not claim to. What the design does is keep the ship-to out of every other place: it is not in the catalog, not in any public record, not in the buyer's own order history on disk (which stores a label), and not in a dispute letter unless the buyer puts it there. It travels inside the sealed letter to the seller.

\paragraph{Linking a buyer's orders.} Separate letters and separate transactions are necessary for unlinkability across sellers, not sufficient. Three channels can still link one buyer's orders: a block explorer, if the node uses one, which sees all watched addresses together; the chain, if payments share inputs or change; and timing, if a buyer places several orders at once and an observer sees them confirm together. The first is removed by using one's own chain data. The second is still open: the node will spend its own unconfirmed change (\S\ref{sec:payments}). The third is only partly addressed, by spacing payments.
