\paragraph{The ship-to ceiling.} For physical goods, the seller and the carrier learn where the buyer receives parcels. No protocol mechanism removes this, and we do not claim to. What the design does is keep the ship-to out of every other place: it is not in the catalog, not in any public record, not in the buyer's own order history on disk (which stores a label), not in a dispute letter unless the buyer puts it there, and, because delivery runs over Tor, not exposed to network observers.

\paragraph{Linking a buyer's orders.} Separate letters and separate transactions are necessary for unlinkability across sellers, not sufficient. Three channels can still link one buyer's orders: a block explorer, if the node uses one, which sees all watched addresses together; the chain, if payments share inputs or change; and timing, if a buyer places several orders at once and an observer sees them confirm together. The first is removed by using one's own chain data, the second by coin selection (\S\ref{sec:payments}), and the third only partly, by spacing payments.
