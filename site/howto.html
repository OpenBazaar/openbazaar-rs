Testnet4 · the desktop app

Download it, open it, and it runs

The app starts its own node and its own Tor client, and stops them when you quit. There is nothing else to install. Every network in these builds is a test network. Do not send real coins.

Install

One file per computer

Download from the latest release. SHA256SUMS on that page lists the checksum of every file.

macOS (Apple silicon and Intel): the .dmg, or the zipped .app. The builds are unsigned, so open the app once, then go to System Settings → Privacy & Security and click Open Anyway.

Windows: the -setup.exe. When SmartScreen says it protected your PC, click More info, then Run anyway.

Linux: the .AppImage (make it executable with chmod +x, then run it), or the .deb for Debian and Ubuntu.

To run a store on an always-on machine and manage it from a phone or laptop over Tor, use the home node instead: the ob-node_*.tar.gz for Linux or macOS, or the Docker image ghcr.io/openbazaar/ob-node. home-node.md inside each archive explains setup and pairing.

The network

Tor, by default

Since 0.1.0-alpha.4 the node runs its own Tor client (Arti) inside the app. There is no setting to turn it on, and none to turn it off. Store reads, chain and indexer queries, exchange rates, and order and escrow mail leave through that client, and your store address is a v3 onion service. A clearnet sale URL is refused before a connection is made.

Builds up to 0.1.0-alpha.3 did not bundle Tor: they used a Tor daemon already running on the machine at 127.0.0.1:9050, and stayed offline without one rather than touch the clear web. If an old build sits silent, that is why. Update instead of installing Tor.

Coins

Monero and Zcash, already on

Monero direct pay is on by default since 0.1.0-alpha.4, on stagenet in these testnet4 builds. The node starts against public stagenet onion daemons, reached through its Tor client. Nothing to configure: a listing priced for Monero can be paid as soon as the app runs.

To use your own monerod instead, write its URL as one line in a file named xmr-daemon in the app's data folder and restart the app. Zcash runs against a public testnet indexer the same way, and a zec-indexer file overrides it. Lightning is on for test payments. No coin in these builds spends real money.

The app's data folder is ~/.local/share/app.openbazaar.desktop on Linux, ~/Library/Application Support/app.openbazaar.desktop on macOS, and %APPDATA%\app.openbazaar.desktop on Windows.

Qubes and minimal Linux

When there is no keyring

The key that encrypts the app's data lives in the OS keyring: the macOS Keychain, the Windows Credential Manager, or on Linux the Secret Service over D-Bus. A plain Fedora or Debian qube usually runs no Secret Service, and builds up to 0.1.0-alpha.4 exited right at startup there, with the reason written only to the node's log.

From 0.1.0-alpha.5 the app says what happened and offers to keep the key in a file in its data folder instead, readable only by your user. It remembers the choice. On an older build, install and start gnome-keyring in the template, or launch with OB_DESKTOP_DATA_DIR=<absolute path>, which runs a separate profile that keeps its key in a file.

When a start fails The reason is the last ob-node: line of testnet4/node.log in the app's data folder. The log stays on your machine; nothing is reported anywhere.
